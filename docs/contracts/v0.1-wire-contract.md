# v0.1 Wire Contract

This record freezes the registration and plain-direct subset used by AWiki Lite CLI.

## Registration

- `POST /user-service/handle/rpc`: `validate` and `send_otp`; registration OTP purpose is
  `awiki.identity.register.v1`.
- `POST /user-service/did-auth/rpc`: `register` with `did_document`, canonical handle,
  normalized phone, and OTP code.
- Requests identify as `X-AWiki-Client-Version: awiki-cli/0714/0.1.0`. The product token is
  intentionally compatible with the server's managed allow-list.
- New documents contain one device. User Service requires the exact canonical bundle recorded in
  `registration.json`, including E2EE/group identifiers. Lite treats these as admission metadata:
  it exposes and sends only `anp.direct.base.v1` traffic.
- Registration returns an exact-device access token. It is the Bearer credential for `/im/rpc`
  and is stored in a separate mode-0600 session file.

## Plain Direct Messaging

- `direct.send` uses `anp.direct.base.v1`, `transport-protected`, an agent DID target,
  `text/plain`, and distinct stable UUID values for `operation_id` and `message_id`.
- `auth.scheme` is `anp-rfc9421-origin-proof-v1`. The ANP SDK signs only
  `method + meta + body`; `auth` is excluded.
- `sync.delta` uses `anp.sync.local.v1` to discover Direct threads for the stateless inbox.
- `sync.thread_after` uses `anp.sync.local.v1` to read complete Direct messages. Inbox results
  retain only messages addressed to the current DID; history retains both directions.
- Explicit read marking still uses `inbox.mark_read` with `anp.inbox.local.v1`.
- Local reads use Bearer hop authentication and do not carry an origin proof. This client never
  sends a device/E2EE selector.

Fixtures contain placeholders, never live phone numbers, OTPs, tokens, proofs, or key material.
