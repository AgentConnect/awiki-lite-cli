# v0.1 Wire Contract

This record freezes the registration and plain-direct subset used by AWiki Lite CLI.

## Registration

- `POST /user-service/v1/handle/rpc`: `validate` and `send_otp`; registration OTP purpose is
  `awiki.identity.register.v1`.
- `POST /user-service/v1/did-auth/rpc`: `register` with `did_document`, canonical handle,
  normalized phone, and OTP code.
- Requests identify as `X-AWiki-Client-Version: awiki-cli/0714/0.2.0`. The product token is
  intentionally compatible with the server's managed allow-list.
- New documents contain one device. User Service requires the exact canonical bundle recorded in
  `registration.json`, including E2EE/group identifiers. Lite treats these as admission metadata:
  it exposes and sends only `anp.direct.base.v1` traffic.
- User DID documents advertise the home Message Service public endpoint at `/anp-im/rpc` for
  remote service discovery. Lite's authenticated local-client calls use `/im/rpc`; these are
  different protocol surfaces.
- Registration returns an exact-device access token. It is the Bearer credential for `/im/rpc`
  and is stored in a separate mode-0600 session file.
- Before publishing a newly registered local identity, Lite calls `sync.bootstrap` with profile
  `anp.sync.local.v2`, `event_schema_max: 1`, and a random opaque `client_instance_id` persisted
  before the request. Lost responses and process retries reuse that ID.
- Lite accepts and persists only a matching-device `tail_only` result. It does not store recovery
  tokens and fails explicitly on `compact_recovery_required`; full snapshot/delta recovery belongs
  to the full AWiki client.

## Plain Direct Messaging

- `direct.send` uses `anp.direct.base.v1`, `transport-protected`, an agent DID target,
  `text/plain`, and distinct stable UUID values for `operation_id` and `message_id`.
- `auth.scheme` is `anp-rfc9421-origin-proof-v1`. The ANP SDK signs only
  `method + meta + body`; `auth` is excluded.
- `inbox.get` uses `anp.inbox.local.v1` for bounded stateless inbox pages.
- `direct.get_history` uses `anp.direct.local.v1` for bounded Direct history pages.
- Explicit read marking still uses `inbox.mark_read` with `anp.inbox.local.v1`.
- Local reads use Bearer hop authentication and do not carry an origin proof. This client never
  sends a device/E2EE selector.
- Read commands never infer sync state from an empty inbox/history page and never call
  `sync.bootstrap`. Older Lite state without sync metadata keeps its legacy read path and can opt
  in with `id init-sync`; new registration bootstraps before publishing the local identity.

Fixtures contain placeholders, never live phone numbers, OTPs, tokens, proofs, or key material.
